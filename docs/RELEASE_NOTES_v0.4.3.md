# ChipMate v0.4.3

这一版是在**真实硬件**上跑出来的。用一块 STC15F2K60S2 教学板（CH340 板载 USB 转串口）把「连接串口 → 烧录 → 校验」全流程走通，并把过程中暴露的 5 个问题修掉。

## 真机验证结果

```
Target model: IAP15F2K61S2      (STC15F2K60S2 的 ISP 自报型号)
Magic: F449    Code flash: 61.0 KB
Target frequency: 11.062 MHz    BSL version: 7.2.2S
Target UID: F449007000E539
Erasing flash: done → Writing flash: 576 Bytes → Finishing write: done
Setting options: done → Disconnected!
```

## 修复

1. **烧录超时会永久占着串口**
   以前 stcgal 等不到握手就一直挂着，串口被独占，用户回监控页直接报「拒绝访问」。现在单协议最多等 180 秒，超时自动终止进程、释放端口，并提示「请确认已按 RST」。

2. **上一次没结束的烧录会阻塞下一次**
   新烧录会先终止残留的 stcgal 进程，日志明确输出「已终止上一次未结束的烧录进程」。

3. **从烧录页切回串口监控拿不到端口**
   进入监控前先杀掉烧录进程并重试 3 次打开端口。实测从 `400 拒绝访问` 变为 `200 ok`。

4. **串口下拉框塞满蓝牙虚拟串口**
   过滤 `BTHENUM` 设备与「蓝牙 / Bluetooth」描述，真 USB 串口排在最前。实测系统 7 个口里只显示 `COM7`。

5. **`-P auto` 在 STC15 上握手失败**
   auto 改为依次尝试 `stc15 → stc8 → stc89`，每轮 25 秒，日志提示「请按一下板上的 RST 复位键」。

6. **烧录提示文案与实际操作不符**
   原来写「给 MCU 断电上电」，但对 USB 供电的板子拔线会让串口设备消失、stcgal 直接退出。现在明确写「按板上的 RST 复位键，**不要拔 USB**」，中英文同步。

7. **端口被别的程序占用时只有英文报错**
   `PermissionError(13, '拒绝访问。')` 后面追加中文提示，指向 STC-ISP / 串口助手占用。

## 升级说明

- 从 v0.4.2 升级可直接覆盖安装；**安装前请退出正在运行的旧版**，否则会提示文件占用
- 如果安装包放在 `frontend\release` 目录里直接双击报 `0xC0000005`，把它复制到别的目录（例如 `D:\tmp`）再运行，这是杀软扫描新 exe 导致的，不是程序问题
- 安装包未做代码签名，首次运行可能被 SmartScreen / 杀软拦一次

## 已知限制

- 真实测试只覆盖 STC15 系列（IAP15F2K61S2）。STC89 / STC8 / STC12 没有硬件验证
- `auto` 的三协议回退逻辑没有在真机上完整走完（需要连续复位三次）
- 烧录完成后板子立即运行新程序，若程序不打印，串口监控会保持静默，这是正常的
