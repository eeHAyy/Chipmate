# ChipMate v0.4.0

第二轮好用度评审的整改：一个安全漏洞、一个让核心卖点失效的目录 bug、一个串口切行问题、一个启动失败黑箱。

## 安全

- **收紧 CORS**：不再 `allow_origins=["*"]`，只放行本机开发端口（5173/5174）与打包页面的 `null` 来源
- **本机访问令牌**：所有写操作（对话、设置、上传、烧录、串口连接/发送/模拟）都需要 `X-ChipMate-Token`；令牌由 Electron 每次启动随机生成并直接注入渲染进程，陌生网页拿不到令牌，无法再白嫖你的 Key 额度
- `/token` 端点只允许本机开发来源读取，陌生 Origin 一律 403

## 修复

- **手册解析结果写错目录（根因级 bug）**：解析器把结果写进了安装目录的 `backend/data`，而列表读的是 `%APPDATA%\ChipMate\data`，两边不是同一处，导致用户拖入的手册**永远显示待上传**。现在统一走用户数据目录，上传后立即生效
- **引脚识别只认 STM32**：正则扩到 `GPIO0/GPIO18`（ESP32、RP2040）与 `PA9/PB0`（STM32、AVR、STC），预设里的 ESP32、ATmega、RP2040 不再是摆设
- **寄存器只认 32 位地址**：`0x[0-9A-F]{2,8}`，8 位/16 位单片机（STC、AVR）的 `0x80`、`0x89` 也能提取
- **LLM 兜底永不触发**：原来只读环境变量 `DEEPSEEK_API_KEY`，安装包用户没有这个变量；现在读设置页里保存的 Key / 接口地址 / 模型
- **串口按行切分**：按 `\n` 切行并保留半包缓冲，跨包分片的日志不再糊成一坨；对不带换行的 `printf` 固件，静默 300ms 后整段输出
- **后端启动失败不再黑箱**：进程起不来或端口被占用时弹窗说明原因，并给出三条排查步骤

## 验证

- 后端 15 个单测通过（新增令牌门禁 5 项、解析器 3 项）
- 手工验证：无令牌 POST 401、错令牌 401、陌生 Origin 取 token 403、本机令牌 200；`GPIO0/GPIO18/PA9/PB0` 与 `0x89/0x40021018` 均能提取；`HardF` + `ault_Handler` 跨包被拼回一行
